# AutoStarter

<!-- language-switcher -->
[English](../README.md) · [Русский](README.ru.md) · [中文](README.zh.md) · [Español](README.es.md) · **العربية** · [Português](README.pt.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [日本語](README.ja.md) · [हिन्दी](README.hi.md)

![AutoStarter — برامجك، وترتيب تشغيلك. مدير لنظام Windows مبني على Tauri وRust.](images/hero.svg)

**مدير لتشغيل البرامج في نظام Windows مع ضبط سلوك النوافذ ودعم شريط النظام.**

يقوم AutoStarter (ويظهر باسم AutoStart Manager في الواجهة) بتشغيل التطبيقات التي تختارها عند بدء تشغيله. أضِف البرامج التي تحتاجها، واضبط سلوكها، وفعِّل التشغيل التلقائي للمدير نفسه — عندها ستبدأ مجموعة تطبيقاتك عند تسجيل الدخول إلى Windows.

المشروع مبني على **Tauri 1 وRust وTypeScript وVite 5**.

> **لنظام Windows فقط.** يستخدم التطبيق السجل (Registry) وواجهة Win32 API؛ ولا يدعم التنفيذ الحالي تشغيل نسخة سطح المكتب أو بناءها على Linux وmacOS.

## الميزات

- **قائمة برامجك الخاصة:** إضافة ملفات `.exe` واختصارات `.lnk` وبرامج نصية `.bat` / `.cmd` عبر مربع حوار اختيار الملفات.
- **تفعيل مستقل:** استثناء برنامج مؤقتًا من التشغيل دون حذفه من القائمة.
- **التحكم في النوافذ:** تشغيل عادي أو مُصغَّر أو مخفي، بالإضافة إلى إرسال أمر إغلاق بعد اكتشاف العملية.
- **التشغيل عند تسجيل الدخول إلى Windows:** بدء المدير تلقائيًا للمستخدم الحالي.
- **دعم شريط النظام:** إخفاء النافذة الرئيسية واستعادتها والخروج عبر قائمة سياق الأيقونة.
- **وضع بلا واجهة:** تشغيل البرامج المفعَّلة ثم إنهاء المدير بعد 30 ثانية.
- **إعدادات محلية:** تُحفظ قائمة البرامج والمعاملات في ملفات JSON.
- **10 لغات للواجهة:** الروسية والإنجليزية والصينية والإسبانية والعربية والبرتغالية والفرنسية والألمانية واليابانية والهندية.

## البداية السريعة

![ثلاث خطوات: أضِف البرامج وفعِّل بطاقاتها، اضبط الأوضاع والتشغيل التلقائي للمدير، ثم سجِّل الدخول إلى Windows. التشغيل اليدوي للمدير يشغِّل أيضًا العناصر المفعَّلة.](images/workflow.svg)

إذا لم يكن التطبيق مبنيًا بعد، فنفِّذ أولًا [تعليمات البناء](#التثبيت-والبناء-من-المصدر).

1. شغِّل `tauri-app.exe` — هذا هو الاسم الحالي للملف التنفيذي للمشروع.
2. افتح الإعدادات بالزر الموجود في الزاوية السفلية اليمنى واختر **Language → العربية**.
3. اضغط **«+ إضافة»** واختر برنامجًا أو ملفًا نصيًا.
4. عند الحاجة، حدِّد **«مُصغَّر»** أو **«مخفي»** أو **«إغلاق»** في بطاقة البرنامج.
5. حوِّل مفتاح البطاقة إلى وضع **«تشغيل»**. العناصر الجديدة معطَّلة افتراضيًا.
6. في الإعدادات فعِّل **«التشغيل التلقائي»** إذا أردت بدء المدير مع البرامج المختارة عند تسجيل الدخول إلى Windows.

تُحفظ التغييرات تلقائيًا. زر الحذف يزيل العنصر من القائمة فقط — ويبقى ملف البرنامج على القرص.

> **مهم:** تعمل البرامج المفعَّلة عند كل بدء جديد لعملية AutoStarter، بما في ذلك البدء اليدوي. إضافة عنصر أو تحويله إلى «تشغيل» لا يشغِّله فورًا. للتحقق من الإعداد، أنهِ المدير تمامًا عبر **Quit** في شريط النظام ثم افتحه من جديد. قد تُشغَّل التطبيقات العاملة بالفعل مرة أخرى.

## أوضاع تشغيل البرامج

| الوضع في البطاقة | السلوك |
| --- | --- |
| دون علامات إضافية | تشغيل عادي عبر `cmd /c start`. |
| **مُصغَّر** | تشغيل عبر `cmd /c start /min` مع طلب نافذة مُصغَّرة. |
| **مخفي** | تشغيل عبر PowerShell `Start-Process -WindowStyle Hidden`. هذا طلب لإخفاء النافذة، وليس ضمانًا لظهور أيقونة البرنامج في شريط النظام. |
| **إغلاق** | تشغيل عادي، ثم البحث عن العملية باسم الملف لمدة 30 ثانية تقريبًا. بعد اكتشافها ينتظر المدير 0.5 ثانية إضافية ويرسل أمر الإغلاق النظامي إلى نوافذ العملية الظاهرة. |
| **إيقاف / تشغيل** | يستثني العنصر أو يضمّه إلى التشغيل عند بدء المدير التالي. |

**الخصائص والقيود:**

- «مُصغَّر» و«مخفي» متعارضان في الواجهة ولا يمكن تفعيلهما معًا.
- «إغلاق» له أولوية على الوضعين ولا يعني الإنهاء القسري للعملية. فقد يُغلق التطبيق المستهدف، أو يُصغَّر إلى شريطه الخاص، أو يعرض مربع حوار، أو يتجاهل الطلب.
- يجري البحث الخاص بـ«إغلاق» حسب اسم الملف، لا حسب المسار الكامل أو معرّف النسخة المُشغَّلة. لذلك قد يؤثر الأمر في عملية عاملة بالفعل تحمل الاسم نفسه. وفي حالة الاختصارات والملفات النصية لا يتطابق اسم الملف المختار عادةً مع اسم العملية الفعلية.
- تدير بعض التطبيقات نوافذها بنفسها وقد تتجاهل التشغيل المخفي أو المُصغَّر.
- لا توفر الواجهة ضبط معاملات سطر الأوامر أو دليل العمل أو فترات تأخير فردية.

أضِف البرامج والملفات النصية الموثوقة فقط. لا تستخدم «إغلاق» مع التطبيقات التي تحتوي على بيانات غير محفوظة دون تجربة مسبقة.

## إعدادات المدير

| الإعداد | ما الذي يفعله |
| --- | --- |
| **اللغة** | يغيّر لغة الواجهة؛ الإنجليزية مختارة افتراضيًا. |
| **البدء في شريط النظام** | يخفي النافذة الرئيسية عند بدء النسخة العادية ويعرض أيقونة في منطقة الإشعارات. |
| **التشغيل التلقائي** | يضيف AutoStarter إلى التشغيل التلقائي في Windows للمستخدم الحالي. معطَّل افتراضيًا. |
| **الإغلاق بعد التنفيذ** | عند التشغيل التلقائي في Windows يضيف الراية `--close-after-30`: يشغِّل المدير البرامج المفعَّلة، وينتظر 30 ثانية، ثم ينتهي دون إنشاء واجهة أو أيقونة شريط النظام. متاح فقط عند تفعيل «التشغيل التلقائي». |

**«إغلاق» في البطاقة و«الإغلاق بعد التنفيذ» في الإعدادات وظيفتان مختلفتان:** الأولى تخص نوافذ البرنامج المختار، والثانية تخص المدير نفسه. مدة الـ30 ثانية ثابتة ولا تعني انتظار انتهاء جميع التطبيقات المُشغَّلة.

البدء اليدوي العادي بدون الراية يفتح المدير وفق إعداد «البدء في شريط النظام»، حتى لو كان «الإغلاق بعد التنفيذ» مفعَّلًا.

### التحكم عبر شريط النظام

- **زر إغلاق النافذة** يخفي المدير في شريط النظام ولا ينهيه.
- **النقر على الأيقونة** أو العنصر **Show** يعيد النافذة الرئيسية.
- **النقر بالزر الأيمن ← Quit** ينهي المدير تمامًا.

تظهر أسماء عناصر قائمة شريط النظام حاليًا بالإنجليزية بغض النظر عن لغة الواجهة.

## التثبيت والبناء من المصدر

### المتطلبات

يتطلب تشغيل النسخة الرسومية **Microsoft Edge WebView2 Runtime**. وبيئة البناء العملية هي Windows 10/11 مع تثبيت ما يلي:

- [Node.js](https://nodejs.org/) **الإصدار 20 أو أحدث** وnpm؛ ويُنصح بإصدار LTS الحالي.
- [Rust](https://rustup.rs/) — سلسلة أدوات stable حديثة لـ Windows MSVC. الحد الأدنى المذكور في `Cargo.toml` هو 1.70، لكن التبعيات في ملف القفل قد تتطلب إصدارًا أحدث.
- [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/) مع مكوّنات **Desktop development with C++** وMSVC وWindows SDK.
- [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/).
- [Git](https://git-scm.com/) لاستنساخ المستودع.

معلومات إضافية: [إعداد بيئة Tauri 1 لنظام Windows](https://v1.tauri.app/v1/guides/getting-started/prerequisites/#setting-up-windows).

### الحصول على المصدر

نفِّذ في PowerShell:

```powershell
git clone https://github.com/BORGERone/AutoStarter.git
cd AutoStarter
npm ci
```

يثبّت `npm ci` التبعيات وفق `package-lock.json`. ويحتاج البناء الأول أيضًا إلى اتصال بالشبكة لتنزيل تبعيات Rust وأدوات التحزيم.

### وضع التطوير

```powershell
npm run tauri-dev
```

أو شغِّل `dev.bat` من مستكشف الملفات. يشغِّل Tauri تلقائيًا Vite على المنفذ **5174** ويفتح نافذة سطح المكتب.

> يشغِّل `npm run dev` واجهة الويب فقط. وفي المتصفح العادي لا تتوفر وظائف Tauri: اختيار الملفات عبر مربع الحوار الأصلي، وحفظ الإعدادات، والتحكم في شريط النظام والسجل. استخدم `npm run tauri-dev` لفحص التطبيق بالكامل.

### البناء مع المثبِّتات

```powershell
npm run tauri-build
```

يبني الأمر الواجهة وتطبيق Rust والحزم المحددة في إعدادات Tauri. وتوجد النتائج في:

- `src-tauri/target/release/tauri-app.exe` — الملف التنفيذي؛
- `src-tauri/target/release/bundle/` — حزم التثبيت التي أنشأها أداة التحزيم.

### البناء دون مثبِّت

```powershell
.\build.bat
```

ينفّذ السكربت على التوالي `npm run build` ثم `cargo build --release` في دليل `src-tauri`. والنتيجة هي `src-tauri/target/release/tauri-app.exe`. ولا تزال الواجهة الرسومية تتطلب WebView2 Runtime.

التشغيل اليدوي لوضع بلا واجهة:

```powershell
.\src-tauri\target\release\tauri-app.exe --close-after-30
```

### فحص الواجهة

```powershell
npm run build
```

ينفّذ الأمر فحص TypeScript وبناء الإنتاج عبر Vite. وهو لا يفحص شيفرة Rust ولا سلوك Win32 API. ولا يوجد حاليًا سكربت اختبارات آلية منفصل في `package.json`.

## تخزين البيانات والتشغيل التلقائي في Windows

تُحفظ إعدادات المستخدم الحالي في الدليل:

```text
%APPDATA%\tauri-launcher\
├── programs.json    # قائمة البرامج والمسارات وأوضاع التشغيل
└── settings.json    # اللغة وإعدادات المدير
```

لأخذ نسخة احتياطية، أنهِ المدير تمامًا وانسخ كلا الملفين. وعند النقل إلى حاسوب آخر، تحقق من مسارات البرامج. ولا تدخل معاملات التشغيل التلقائي في السجل ضمن هذه النسخة: بعد النقل، فعِّل التشغيل التلقائي من جديد من نسخة التطبيق المطلوبة.

عند تفعيل «التشغيل التلقائي» تُنشأ القيمة **`AutoStartManager`** في المفتاح:

```text
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
```

ويُحفظ فيها مسار الملف التنفيذي الحالي للمدير، وعند الحاجة الراية `--close-after-30`. وهذا تشغيل **عند تسجيل دخول المستخدم الحالي**، وليس خدمة نظام. ولا تُنشأ إدخالات منفصلة لكل برنامج مضاف؛ كما لا يدير المديرُ التشغيلَ التلقائي القائم للتطبيقات الأخرى.

**عطِّل «التشغيل التلقائي» قبل نقل الملف التنفيذي أو حذفه.** وبعد النقل، افتح المدير من الموقع الجديد وفعِّله مرة أخرى. ولإعادة ضبط كاملة، عطِّل التشغيل التلقائي أولًا، وأنهِ التطبيق عبر Quit، ثم احذف الدليل `%APPDATA%\tauri-launcher` — سيؤدي ذلك إلى حذف القائمة المحفوظة والإعدادات.

## الأسئلة الشائعة

**أضفت برنامجًا لكنه لا يعمل.**

تحقق من مفتاح «تشغيل» في بطاقته ومن وجود الملف في المسار المحدد. أعد تشغيل المدير بالكامل: فتغيير القائمة وحده لا يشغِّل شيئًا. وللتشغيل عند الدخول إلى Windows يجب أيضًا تفعيل «التشغيل التلقائي» في إعدادات المدير.

**التطبيقات تُفتح مرتين.**

لا يتحقق AutoStarter مما إذا كان البرنامج يعمل مسبقًا. تحقق من إعداد التشغيل التلقائي الخاص به ومن قائمة بدء التشغيل في Windows. كما أن إعادة تشغيل المدير نفسه تعيد تشغيل جميع العناصر المفعَّلة.

**بعد الضغط على زر الإغلاق ما زال المدير يعمل.**

هذا هو السلوك المتوقع. ابحث عن أيقونة AutoStart Manager في منطقة الإشعارات، ووسِّع الأيقونات المخفية عند الحاجة، ثم اختر Quit.

**لا يظهر التطبيق بعد تسجيل الدخول إلى Windows.**

تحقق من «البدء في شريط النظام» و«الإغلاق بعد التنفيذ»: في الحالة الأولى تكون النافذة مخفية، وفي الثانية لا تُنشأ واجهة إطلاقًا. ولتغيير الإعدادات شغِّل الملف التنفيذي يدويًا دون الراية `--close-after-30`.

**البناء لا يجد الرابط (linker) أو Windows SDK.**

تحقق من تثبيت C++ Build Tools وسلسلة أدوات MSVC لـ Rust، ثم أعد تشغيل الطرفية. وفي حال مشكلات عرض النافذة تحقق من وجود WebView2 Runtime.

**وضع التطوير يبلّغ بأن المنفذ مشغول.**

حرِّر المنفذ 5174، مثلًا بإنهاء نسخة Vite السابقة. ويُستخدم المنفذ في إعدادات Vite وإعدادات Tauri معًا.

## بنية المشروع

```text
AutoStarter/
├── index.html                 # ترميز النافذة الرئيسية والإعدادات
├── src/
│   ├── main.ts                # الواجهة والترجمات واستدعاءات Tauri
│   └── styles.css             # أنماط التطبيق
├── src-tauri/
│   ├── src/main.rs            # تشغيل البرامج وJSON والسجل وشريط Win32
│   ├── Cargo.toml             # تبعيات Rust ومعاملاتها
│   ├── Cargo.lock             # تبعيات Rust المثبَّتة
│   ├── build.rs               # سكربت بناء Tauri
│   └── tauri.conf.json        # النافذة والأذونات والتحزيم
├── icon.ico                   # أيقونة التطبيق وشريط النظام
├── package.json               # أوامر npm وتبعيات الواجهة
├── package-lock.json          # تبعيات npm المثبَّتة
├── vite.config.ts             # إعدادات Vite
├── build.bat                  # بناء Release بدون مثبِّت
└── dev.bat                    # تشغيل وضع التطوير
```

## المساهمة في التطوير

يمكن ترك تقارير الأخطاء والاقتراحات في [Issues](https://github.com/BORGERone/AutoStarter/issues). ولتقرير قابل لإعادة الإنتاج، اذكر إصدار Windows وطريقة التشغيل أو البناء والخطوات والسلوك المتوقع. وقبل نشر السجلات أو ملفات JSON احذف البيانات الشخصية والمسارات الخاصة.

لتغييرات الواجهة نفِّذ `npm run build`؛ أما تغييرات التشغيل والسجل وشريط النظام فتحقق منها إضافيًا في نسخة سطح المكتب على Windows. ويُفضَّل إرفاق طلب السحب بوصف للتغييرات والفحوص التي أُجريت.
