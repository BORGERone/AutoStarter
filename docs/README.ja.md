![AutoStarter — あなたのプログラムを、あなたの順序で起動。Tauri と Rust で作られた Windows 向けマネージャー。](images/hero.svg)

**ウィンドウの動作設定とシステムトレイ対応を備えた、Windows 向けプログラム起動マネージャー。**

AutoStarter（インターフェイス上の名称は AutoStart Manager）は、自身の起動時に選択したアプリケーションを実行します。必要なプログラムを追加し、その動作を設定して、マネージャー自体の自動起動を有効にすれば、Windows へのサインイン時にアプリ一式が起動します。

本プロジェクトは **Tauri 1、Rust、TypeScript、Vite 5** で構築されています。

> **Windows 専用。** 本アプリケーションはレジストリと Win32 API を使用します。現在の実装では、Linux や macOS でのデスクトップ版の実行およびビルドはサポートされていません。

## 機能

- **独自のプログラム一覧：** ファイル選択ダイアログから `.exe`、`.lnk` ショートカット、`.bat` / `.cmd` スクリプトを追加できます。
- **個別の有効化：** 一覧から削除せずに、プログラムを一時的に起動対象から外せます。
- **ウィンドウ制御：** 通常・最小化・非表示での起動に加え、プロセス検出後に終了コマンドを送信できます。
- **Windows サインイン時の起動：** 現在のユーザー向けにマネージャーを自動起動します。
- **トレイ対応：** アイコンのコンテキストメニューからメインウィンドウの非表示・復元・終了が行えます。
- **インターフェイスなしモード：** 有効なプログラムを起動し、30 秒後にマネージャーを終了します。
- **ローカル設定：** プログラム一覧と各種パラメーターは JSON ファイルに保存されます。
- **10 言語のインターフェイス：** ロシア語、英語、中国語、スペイン語、アラビア語、ポルトガル語、フランス語、ドイツ語、日本語、ヒンディー語。

## クイックスタート

![3 つのステップ：プログラムを追加してカードを有効にし、モードとマネージャーの自動起動を設定して、Windows にサインインします。マネージャーを手動で起動した場合も有効な項目が実行されます。](images/workflow.svg)

アプリケーションがまだビルドされていない場合は、先に[ビルド手順](#ソースからのインストールとビルド)を実行してください。

1. `tauri-app.exe` を実行します。これが現在の本プロジェクトの実行ファイル名です。
2. 右下のボタンから設定を開き、**Language → 日本語** を選択します。
3. **「+ 追加」** をクリックし、プログラムまたはスクリプトを選択します。
4. 必要に応じて、プログラムのカードで **「最小化」**、**「非表示」**、**「閉じる」** をオンにします。
5. カードのスイッチを **「On」** に切り替えます。新しい項目は既定で無効です。
6. Windows サインイン時にマネージャーと選択したプログラムを起動したい場合は、設定で **「自動起動」** を有効にします。

変更は自動的に保存されます。削除ボタンは一覧から項目を取り除くだけで、プログラムのファイル自体はディスク上に残ります。

> **重要：** 有効なプログラムは、手動起動も含め、AutoStarter プロセスが新たに起動するたびに実行されます。項目を追加したり「On」に切り替えたりしても、その場では起動しません。設定を確認するには、トレイの **Quit** でマネージャーを完全に終了してから、もう一度開いてください。すでに動作中のアプリケーションが重複して起動する場合があります。

## プログラムの起動モード

| カード上のモード | 動作 |
| --- | --- |
| 追加のチェックなし | `cmd /c start` による通常の起動。 |
| **最小化** | `cmd /c start /min` による起動で、最小化されたウィンドウを要求します。 |
| **非表示** | PowerShell の `Start-Process -WindowStyle Hidden` による起動。これはウィンドウを隠すための要求であり、プログラムのアイコンがトレイに表示されることを保証するものではありません。 |
| **閉じる** | 通常どおり起動したあと、約 30 秒間ファイル名でプロセスを検索します。検出後、マネージャーはさらに 0.5 秒待ってから、そのプロセスの表示中のウィンドウにシステムの終了コマンドを送信します。 |
| **Off / On** | 次回のマネージャー起動時に、その項目を起動対象から外す、または対象に含めます。 |

**特徴と制限：**

- 「最小化」と「非表示」はインターフェイス上で排他です。
- 「閉じる」は上記 2 つのモードより優先されますが、プロセスの強制終了を意味するものではありません。対象のアプリケーションは、終了する、独自のトレイに最小化する、ダイアログを表示する、あるいは要求を無視することがあります。
- 「閉じる」の検索はファイル名で行われ、フルパスや起動したインスタンスの識別子では行われません。そのため、同名ですでに動作中のプロセスに影響する可能性があります。ショートカットやスクリプトの場合、選択したファイル名は実際のプロセス名と一致しないのが普通です。
- 一部のアプリケーションは自身でウィンドウを管理しており、非表示や最小化での起動を無視することがあります。
- コマンドライン引数、作業ディレクトリ、個別の遅延の設定はインターフェイスでは用意されていません。

信頼できるプログラムとスクリプトのみを追加してください。未保存のデータがあるアプリケーションに対しては、事前の確認なしに「閉じる」を使わないでください。

## マネージャーの設定

| 設定 | 内容 |
| --- | --- |
| **言語** | インターフェイスの言語を変更します。既定では英語が選択されています。 |
| **トレイで起動** | 通常版の起動時にメインウィンドウを隠し、通知領域にアイコンを表示します。 |
| **自動起動** | 現在のユーザー向けに AutoStarter を Windows の自動起動へ追加します。既定では無効です。 |
| **実行後に閉じる** | Windows の自動起動時に `--close-after-30` フラグを追加します。マネージャーは有効なプログラムを起動し、30 秒待ってから、インターフェイスとトレイアイコンを作成せずに終了します。「自動起動」が有効な場合のみ利用できます。 |

**カードの「閉じる」と設定の「実行後に閉じる」は別の機能です。** 前者は選択したプログラムのウィンドウに関するもので、後者はマネージャー自身に関するものです。30 秒という間隔は固定で、起動したすべてのアプリケーションの終了を待つという意味ではありません。

フラグなしの通常の手動起動では、「実行後に閉じる」が有効でも、「トレイで起動」の設定に従ってマネージャーが開きます。

### トレイからの操作

- **ウィンドウの閉じるボタン**は、マネージャーを終了せずトレイに隠します。
- **アイコンのクリック**または **Show** の項目でメインウィンドウが戻ります。
- **右クリック → Quit** でマネージャーを完全に終了します。

トレイメニューの項目名は、インターフェイスの言語にかかわらず、現在は英語で表示されます。

## ソースからのインストールとビルド

### 必要要件

グラフィカル版の実行には **Microsoft Edge WebView2 Runtime** が必要です。実用的なビルド環境は、以下をインストールした Windows 10/11 です。

- [Node.js](https://nodejs.org/) **20 以降**と npm。現行の LTS 版を推奨します。
- [Rust](https://rustup.rs/) — Windows MSVC 向けの現行 stable ツールチェーン。`Cargo.toml` では最低 1.70 と指定されていますが、lock ファイルの依存関係がより新しいバージョンを要求する場合があります。
- [Visual Studio Build Tools](https://visualstudio.microsoft.com/visual-cpp-build-tools/)（**Desktop development with C++** コンポーネント、MSVC、Windows SDK を含む）。
- [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/en-us/microsoft-edge/webview2/)。
- リポジトリのクローン用に [Git](https://git-scm.com/)。

詳細情報：[Windows 向け Tauri 1 環境の準備](https://v1.tauri.app/v1/guides/getting-started/prerequisites/#setting-up-windows)。

### ソースの取得

PowerShell で次を実行します。

```powershell
git clone https://github.com/BORGERone/AutoStarter.git
cd AutoStarter
npm ci
```

`npm ci` は `package-lock.json` に従って依存関係をインストールします。初回ビルドでは、Rust の依存関係やパッケージングツールをダウンロードするためにネットワーク接続も必要です。

### 開発モード

```powershell
npm run tauri-dev
```

またはエクスプローラーから `dev.bat` を実行します。Tauri は自動的にポート **5174** で Vite を起動し、デスクトップウィンドウを開きます。

> `npm run dev` は Web インターフェイスのみを起動します。通常のブラウザーでは Tauri の機能（ネイティブダイアログによるファイル選択、設定の保存、トレイやレジストリの操作）は利用できません。アプリケーションを完全に確認するには `npm run tauri-dev` を使用してください。

### インストーラー付きビルド

```powershell
npm run tauri-build
```

このコマンドは、インターフェイス、Rust アプリケーション、および Tauri の設定で指定されたパッケージをビルドします。結果は次の場所にあります。

- `src-tauri/target/release/tauri-app.exe` — 実行ファイル。
- `src-tauri/target/release/bundle/` — バンドラーが作成したインストールパッケージ。

### インストーラーなしのビルド

```powershell
.\build.bat
```

このスクリプトは `src-tauri` ディレクトリで `npm run build` と `cargo build --release` を順に実行します。結果は `src-tauri/target/release/tauri-app.exe` です。グラフィカルインターフェイスには引き続き WebView2 Runtime が必要です。

インターフェイスなしモードの手動実行：

```powershell
.\src-tauri\target\release\tauri-app.exe --close-after-30
```

### インターフェイスの検証

```powershell
npm run build
```

このコマンドは TypeScript のチェックと Vite の本番ビルドを実行します。Rust コードや Win32 API の挙動は検証しません。現在 `package.json` に自動テスト用の個別スクリプトはありません。

## データの保存場所と Windows の自動起動

現在のユーザーの設定は次のディレクトリに保存されます。

```text
%APPDATA%\tauri-launcher\
├── programs.json    # プログラム一覧、パス、起動モード
└── settings.json    # 言語とマネージャーの設定
```

バックアップを取るには、マネージャーを完全に終了して両方のファイルをコピーしてください。別のコンピューターへ移す場合は、プログラムのパスを確認してください。レジストリ内の自動起動の設定はこのコピーに含まれません。移行後は、使用したいアプリケーションのインスタンスから自動起動を改めて有効にしてください。

「自動起動」を有効にすると、次のキーに値 **`AutoStartManager`** が作成されます。

```text
HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run
```

ここにはマネージャーの現在の実行ファイルのパスと、必要に応じて `--close-after-30` フラグが保存されます。これは**現在のユーザーのサインイン時の起動**であり、システムサービスではありません。追加した各プログラムに対して個別のエントリーは作成されません。また、他のアプリケーションの既存の自動起動をマネージャーが管理することもありません。

**実行ファイルを移動または削除する前に「自動起動」を無効にしてください。** 移動後は、新しい場所からマネージャーを開いて改めて有効にします。完全にリセットするには、まず自動起動を無効にし、Quit でアプリケーションを終了してから、`%APPDATA%\tauri-launcher` ディレクトリを削除してください。これにより、保存された一覧と設定が削除されます。

## よくある質問

**プログラムを追加したのに起動しません。**

カードの「On」スイッチと、指定したパスにファイルが存在するかを確認してください。マネージャーを完全に再起動してください。一覧を変更しただけでは何も起動しません。Windows サインイン時に起動するには、マネージャーの設定で「自動起動」も有効にする必要があります。

**アプリケーションが二重に開きます。**

AutoStarter はプログラムがすでに起動しているかを確認しません。そのプログラム自身の自動起動設定と、Windows のスタートアップ一覧を確認してください。マネージャー自体を再起動した場合も、有効なすべての項目が再度実行されます。

**閉じるボタンを押してもマネージャーが動作し続けます。**

これは想定どおりの動作です。通知領域で AutoStart Manager のアイコンを探し（必要なら隠れているアイコンを展開して）、Quit を選択してください。

**Windows にサインインしてもアプリケーションが表示されません。**

「トレイで起動」と「実行後に閉じる」を確認してください。前者ではウィンドウが隠れ、後者ではインターフェイス自体が作成されません。設定を変更するには、`--close-after-30` フラグを付けずに実行ファイルを手動で起動してください。

**ビルドでリンカーまたは Windows SDK が見つかりません。**

C++ Build Tools と Rust の MSVC ツールチェーンのインストール状況を確認し、ターミナルを再起動してください。ウィンドウの表示に問題がある場合は、WebView2 Runtime の有無を確認してください。

**開発モードでポートが使用中と表示されます。**

たとえば以前の Vite インスタンスを終了して、ポート 5174 を解放してください。このポートは Vite の設定と Tauri の設定の両方で使用されています。

## プロジェクト構成

```text
AutoStarter/
├── index.html                 # メインウィンドウと設定のマークアップ
├── src/
│   ├── main.ts                # インターフェイス、翻訳、Tauri の呼び出し
│   └── styles.css             # アプリケーションのスタイル
├── src-tauri/
│   ├── src/main.rs            # プログラムの起動、JSON、レジストリ、Win32 トレイ
│   ├── Cargo.toml             # Rust の依存関係とパラメーター
│   ├── Cargo.lock             # 固定された Rust の依存関係
│   ├── build.rs               # Tauri のビルドスクリプト
│   └── tauri.conf.json        # ウィンドウ、権限、パッケージング
├── icon.ico                   # アプリケーションとトレイのアイコン
├── package.json               # npm コマンドとインターフェイスの依存関係
├── package-lock.json          # 固定された npm の依存関係
├── vite.config.ts             # Vite の設定
├── build.bat                  # インストーラーなしのリリースビルド
└── dev.bat                    # 開発モードの起動
```

## 開発への参加

不具合の報告や提案は [Issues](https://github.com/BORGERone/AutoStarter/issues) に投稿できます。再現可能な報告のために、Windows のバージョン、起動またはビルドの方法、手順、期待される動作を記載してください。ログや JSON ファイルを公開する前に、個人情報やプライベートなパスは削除してください。

インターフェイスの変更では `npm run build` を実行してください。起動、レジストリ、トレイに関する変更は、Windows のデスクトップ版でも追加で確認してください。プルリクエストには、変更内容と実施した確認の説明を添えることが望まれます。
